# 오더블럭(Order Block) 스윙 매매 전략 — 기획서

> 상태: **실전 구현 (2026-10-24)** — 사용자 결정으로 실전 연동 · 작성·확정 2026-10-24
> 검증: 6.5년(2020-05~2024-12)·203종목, 비용·슬리피지 반영 — 학습 −0.08R(t −1.1) / 검증 −0.20R(t −2.9),
>       같은 청산·수량에 무작위 진입한 대조군보다 나쁘다 (검증 기간 하위 22%). 수익 우위는 확인되지 않았다
> 대상: 실전 `TradingStrategy` 신규 전략 + 백테스트 `BacktestStrategy` 신규 전략
> 가칭 SWING_TYPE: **`O`** (표시 이름 "오더블럭")

이 문서는 "정확히 언제 사고 언제 파는가"를 코드 작성 전에 고정하기 위한 것이다.
수치는 모두 **초기값(백테스트 튜닝 대상)** 이며, 구현 시 클래스 상수로 두고 `describe()`도 같은 상수로 조립한다.

## 0. 참고한 기존 전략 — 단일 이평선(`SingleEMAStrategy`, SWING_TYPE `S`)의 실제 동작

`base_single_ema.py` / `single_ema_strategy.py` / `single_ema_backtest_strategy.py` / `auto_swing_batch.py` 코드 기준.
(`trading/strategies/README.md`는 OBV z>0 게이트, 2단계 익절 등 **옛 동작**이 남아 있어 코드와 다르다 — 아래가 현재 실제 동작)

| 구분 | 단일 이평선의 현재 동작 |
|------|------------------------|
| 판정 주기 | 5분마다 (`trade_job`), 현재가·당일 고저·누적거래량으로 지표를 **증분 계산** |
| 지표 원천 | 장 시작 전 워밍업이 **완성봉**(STOCK_DAY_HISTORY)으로 계산해 Redis `indicators:{st_code}`에 저장 |
| 매수 필터 | 당일 등락률 ±5% 초과 차단 / 전일 윗꼬리 ≥ 40% 차단 / 현재가 < 전일 저가(갭 하락) 차단 |
| 매수 조건 | 현재가 > 실시간 EMA20 이고 EMA20 대비 +6% 이내, +DI > -DI, ADX > 15, accum > 1.0 (OBV vs OBV EMA12) |
| 연속 확인 | 2회 연속(약 10분) — Redis `entry:{swing_id}` (백테스트는 1회) |
| 수량 | `CUR_AMOUNT × 0.8 × conviction(OBV·ADX, 0.4~1.0)` / 전량 모드 0.99, 유동성 필터(일평균 거래대금 5%) |
| 청산 | **단일 청산선(래칫)**: 시작 `max(진입가−ATR×2, 진입가−7%)` → 고점 +20% 본전 → +30% `고점−ATR×4` |
| 부분익절 | +50% 도달 시 절반 (SIGNAL 1→2, 1회) |
| 매도 후 | SIGNAL 3 → OBV z < −0.5 → SIGNAL 4 → OBV z > 0.5 → SIGNAL 0 |
| ATR | 청산선 폭은 **완성봉 ATR** (실시간 ATR은 장 초반 작게 나와 조기 청산) |
| 백테스트 | 일봉, 매수 게이트는 **전일 완성봉**으로 판정(선견 방지), PEAK는 전일 고가까지만 반영 |

### 오더블럭 전략이 그대로 물려받을 것

- SIGNAL 0~4 상태 체계와 엔티티 전이 메서드(`transition_to_buy`, `transition_to_partial`, `reset_cycle`, 쿨다운 전이) — **새 상태 추가 없음**
- 5분 사이클 + 연속 2회 확인, 신호 1회당 단일 주문, 유동성 필터(`MAX_ADV_RATIO`), 전량 모드(`FULL_ENTRY_YN`)
- 래칫형 단일 청산선 (내려가지 않음), 청산 폭은 완성봉 ATR
- 존 판정은 **완성봉만** 사용 (STOCK_DAY_HISTORY 불변식), 백테스트에서 선견 금지
- 매도 후 OBV 기반 쿨다운 (SIGNAL 3→4→0) — 배치 `_handle_cooling_down`이 전략 상수만 읽으므로 그대로 동작

### 성격 차이 (왜 별도 전략인가)

| | 단일 이평선 | 오더블럭 |
|---|---|---|
| 진입 철학 | **돌파 추종** — EMA 위로 올라선 직후 탄다 | **되돌림 매수** — 상승 구조가 확인된 뒤 기관 매집 구간까지 내려올 때 산다 |
| 손절 근거 | 변동성(ATR) | **구조**(오더블럭 하단이 깨지면 가설이 틀림) |
| 진입 빈도 | 상대적으로 잦음 | 드묾 (존 형성 → 미터치 → 첫 리테스트까지 기다림) |
| 손익비 | 추세 길이에 의존 | 손절폭이 좁아 R 단위로 관리 (2R 부분익절) |

## 1. 용어 정의

| 용어 | 정의 |
|------|------|
| 스윙 고점 (Pivot High) | 봉 j의 고가가 앞뒤 `PIVOT_LEN`(=2)봉 고가보다 모두 높을 때. **j+2봉이 완성돼야 확정**된다 (선견 주의) |
| BOS (Break of Structure) | 완성봉 종가가 **가장 최근 확정된 스윙 고점의 고가**를 상향 돌파 |
| 임펄스 구간 | 오더블럭 다음 봉 ~ BOS 봉 |
| 상승 오더블럭 (Bullish OB) | BOS를 만든 임펄스 직전의 **마지막 음봉**(종가 < 시가) |
| 근접선 (Proximal) | OB 캔들 **고가** — 가격이 내려오며 처음 닿는 선, 매수 기준선 (`PROXIMAL_SOURCE`: `"high"` 기본 / `"body"` 몸통 상단=음봉 시가 / `"mean"` OB 50%) |
| 원격선 (Distal) | OB 캔들 **저가** — 손절 기준. 장중에 이 아래로 내려가면 그날 매수하지 않는다 |
| 존 (Zone) | [원격선, 근접선] |
| 터치(Mitigation) | 형성 이후 어떤 봉의 저가가 근접선 이하로 내려옴 |
| R | 진입가 − 손절가 (1트레이드 위험 단위) |

> 하락 오더블럭(매도 진입)은 다루지 않는다 — 현물 롱 전용 시스템이다.

## 2. 오더블럭 탐지 (완성봉, 장 시작 전 워밍업에서 계산)

### 2.1 탐지 알고리즘

```
입력: 완성 일봉 df (STOCK_DAY_HISTORY), ATR14, avg_vol20, EMA120

for k in (최근 OB_MAX_AGE 봉 범위):                     # k = BOS 후보 봉
    ph = k 시점에 '확정되어 있던' 가장 최근 스윙 고점      # j+PIVOT_LEN ≤ k-1 인 피벗만
    if close[k] <= ph.high:  continue                  # BOS 아님

    # 오더블럭: k에서 거꾸로 OB_SEARCH_BARS(=10)봉 안의 마지막 음봉
    ob = k-1부터 역순 탐색, close < open 인 첫 봉
    if ob 없음: continue

    # 품질 조건 (모두 충족)
    1) 변위(Displacement):  close[k] − ob.low ≥ DISPLACEMENT_ATR(2.0) × ATR[k]
    2) 거래량:              임펄스 구간 최대 거래량 ≥ IMPULSE_VOL_RATIO(1.5) × avg_vol20[k]
    3) 존 폭:               ob.high − ob.low ≤ MAX_ZONE_ATR(1.5) × ATR[k]   (너무 넓으면 R이 커진다)
    4) 장기 추세:            close[k] > EMA120[k]

    후보 = (proximal=ob.high, distal=ob.low, ob_date, bos_date=k)
```

구현 세부 규칙 (`app/domain/swing/order_block.py`):

| 항목 | 규칙 |
|------|------|
| 기준 고점 | 봉 k에서 `확정 시점(j+PIVOT_LEN) ≤ k−1`인 스윙 고점 중 가장 최근 것 (동률 고가는 스윙 고점 아님) |
| BOS 1회성 | 한 고점은 **처음으로 종가가 넘은 봉**에서만 BOS. 이후 봉이 또 넘어도 새 BOS 아님 |
| 중복 | 서로 다른 BOS가 같은 음봉을 가리키면 먼저 생긴 BOS 하나만 |
| 품질 지표 시점 | ATR·20일 평균거래량·EMA120은 BOS 봉 k의 값 (k는 완성봉이라 선견 아님), NaN이면 제외 |

### 2.2 유효성 (매일 워밍업에서 다시 판정)

후보 중 아래를 모두 만족하는 것만 **활성 OB**. 여러 개면 **가장 최근에 형성된 것 1개**만 쓴다.

| 조건 | 내용 |
|------|------|
| 미터치 | BOS 봉 **다음 날부터 전일까지** 완성봉 저가가 한 번도 근접선 이하로 내려온 적 없음 (첫 리테스트만 매매). BOS가 전일이면 확인 구간이 비어 활성 |
| 유효 기간 | BOS 이후 `OB_MAX_AGE`(=40) 거래일 이내 |

- "미터치"를 완성봉 기준으로 정의하는 이유: 장중에 존을 건드렸는데 필터 때문에 못 샀다면, 다음 날 워밍업에서 **자동으로 소멸**한다. 실전과 백테스트가 같은 규칙으로 OB를 소비하게 된다.
- **원격선 아래 마감(붕괴)은 따로 검사하지 않는다** — 원격선 ≤ 근접선이라 붕괴는 항상 터치를 포함한다.
- **이미 매수한 OB는 따로 기록하지 않는다** — 매수는 반드시 존 터치일에 일어나므로 다음 날 미터치 규칙으로 소멸한다.
  남는 구멍인 **같은 날 재진입**(손절 → 쿨다운이 장중에 다 지나감)만 Redis `ob_used:{swing_id}:{전일 날짜}`로 막는다.
- 탐지 결과는 Redis `ob_zone:{st_code}`에 저장 (지표 캐시 `indicators:{st_code}`와 분리 — 단일 이평선 스윙이 같은 종목을 써도 서로 영향 없음).
  활성 OB가 없거나 계산에 실패하면 **키를 지운다** (어제 존으로 오늘 매수하지 않도록).

## 3. 매수 (SIGNAL 0 → 1)

### 3.1 매수 조건 — 5분 사이클마다 모두 충족

| # | 조건 | 비고 |
|---|------|------|
| 1 | 활성 OB 존재 (`ob_zone:{st_code}`) | 없으면 판정 자체 스킵 |
| 2 | **당일 저가 ≤ 근접선** (존 터치) | 현재가 조회의 당일 저가 사용 |
| 3 | **원격선 < 현재가 ≤ 근접선 + ENTRY_CHASE_ATR(0.25) × ATR** | 존 안이거나 막 반등한 직후만. 멀리 튄 뒤엔 R이 나빠져 추격 안 함 |
| 4 | 장중 원격선 이탈 이력 없음 | 오늘 현재가가 한 번이라도 원격선 아래였으면 당일 무효 (Redis `ob_broken:{st_code}:{전일 날짜}`, 24h) |
| 5 | 손절폭 ≤ `MAX_STOP_LOSS_PCT`(7%) | 손절가는 3.3 참고. 넘으면 **손절을 줄이지 않고 진입을 포기** |
| 6 | 위 조건이 **2회 연속(약 10분)** 충족 | 단일 이평선과 같은 `entry:{swing_id}` 연속성 로직 |

### 3.2 매수 차단 필터

| 필터 | 내용 | 단일 이평선과 비교 |
|------|------|-------------------|
| 갭 붕괴 | 당일 시가 < 원격선 → OB 즉시 무효 | 단일 이평선의 "전일 저가" 대신 **원격선** 기준 |
| 유동성 | 매수금액 > 일평균 거래대금 × 5% 차단 | 동일 (배치 공통) |
| 실보유 대조 | 실보유 있으면 신규 매수 대신 편입 | 동일 (배치 공통) |

> 단일 이평선의 "전일 윗꼬리 40%" 필터는 쓰지 않는다 — 되돌림 구간에서는 윗꼬리 음봉이 흔해 진입 기회를 대부분 막는다.
>
> **급락 필터(당일 등락률)도 쓰지 않는다 (2026-10-24 제거).** 처음엔 "당일 −5% 미만 차단"을 두었으나, 존까지의 되돌림이
> 하루에 크게 오면 바로 그 첫 리테스트를 막았다 (1단계 백테스트: 존 터치 16회 중 6회 차단). "존이 뚫리는 중"인지는
> 갭 붕괴·장중 원격선 이탈(3.1 #4)·손절폭 상한(3.1 #5)이 직접 확인한다.

### 3.3 손절가 (매수 시 확정, 이후 고정)

```
STOP = 원격선 − STOP_ATR_BUFFER(0.3) × ATR(완성봉)
R    = 진입가 − STOP
```

- 원격선 바로 아래에 두면 꼬리 노이즈에 털리므로 ATR 버퍼를 둔다.
- **매수 시점에 확정해 저장**해야 한다 (OB는 다음 날 소비·갱신되므로 청산 때 다시 계산할 수 없다) → 6.1 `SWING_TRADE.STOP_PRICE`.
- 단일 이평선과의 차이: 단일 이평선의 시작 손절선(`max(진입가 − ATR×2, 진입가 −7%)`)은 저장하지 않고 매 사이클 그날의 완성봉 ATR로 재계산하므로 날마다 오르내린다. 오더블럭은 근거가 구조(원격선)라 매수 시 값을 고정한다.

### 3.4 수량 — 위험 기반 (R 사이징)

```
risk_qty = int(CUR_AMOUNT × RISK_PER_TRADE(0.02) / R)        # 손절 시 배정금의 2%만 잃도록
cap_qty  = int(CUR_AMOUNT × MAX_ENTRY_PCT(0.8) / 현재가)       # 단일 이평선과 같은 상한
qty      = min(risk_qty, cap_qty)
전량 모드(FULL_ENTRY_YN='Y'): qty = int(CUR_AMOUNT × 0.99 / 현재가)   # 손절폭 7% 이내는 이미 보장됨
```

- 예: 손절폭 4% → 2%/4% = 배정금의 50% 투입 / 손절폭 2% → 100% → 상한 80%.
- conviction(OBV·ADX) 대신 R 사이징을 쓰는 이유: 이 전략의 손절은 구조적이라 손절폭이 매번 다르다. 손절폭이 넓을수록 적게 사야 손실이 일정해진다.

## 4. 매도 (SIGNAL 1/2 → 3)

### 4.1 단일 청산선 (래칫, 매 사이클 재계산·하향 없음)

```
peak_gain_R = (PEAK − 진입가) / R          # PEAK는 기존처럼 5분 샘플 현재가로 갱신

단계 1 (진입 시)      : exit = STOP
단계 2 (고점 ≥ +1R)   : exit = max(exit, 진입가)                      # 본전 확보
단계 3 (고점 ≥ +2R)   : exit = max(exit, PEAK − TRAIL_ATR_MULT(3.0) × ATR)   # 추세 추종

현재가 ≤ exit → 잔량 전량 매도 → SIGNAL 3 (reset_cycle)
```

| 매도 사유(`reasons`) | 조건 |
|---------------------|------|
| `손절` | 고점이 +1R 미만에서 이탈 (구조 붕괴) |
| `본전방어` | +1R ~ +2R 사이에서 이탈 |
| `이익확정` | +2R 이상에서 트레일링 이탈 |

단일 이평선과의 차이: 활성 기준이 **% 수익률(+20%/+30%)이 아니라 R 배수**. 손절폭이 3%인 트레이드에서 +20%를 기다리면 본전 방어가 사실상 작동하지 않기 때문.

### 4.2 부분 익절 (SIGNAL 1 → 2, 1회)

- 현재가 ≥ 진입가 + `PARTIAL_TP_R`(2.0) × R → 보유 수량의 50% 매도
- 1주뿐이면 전량 매도 (기존 배치 로직 그대로)
- 부분익절 후에도 PEAK는 리셋하지 않는다 (잔량은 4.1 단계 3 트레일링으로 계속 추적)

### 4.3 매도 후 쿨다운 (SIGNAL 3 → 4 → 0)

- 단일 이평선과 동일한 OBV z 2단계 (`COOLDOWN_OBV_EXIT = −0.5`, `COOLDOWN_OBV_REENTRY = 0.5`).
- 추가로 **이미 매매한 OB는 재사용 금지** (2.2 — 다음 날부터는 미터치 규칙, 같은 날은 `ob_used`). SIGNAL 0으로 돌아와도 **새 BOS로 새 OB가 생겨야** 다시 매수한다.

## 5. 상태 흐름 요약

```
[워밍업 08:29 / 미국 장 전]  완성봉으로 OB 탐지 → ob_zone:{st_code}

SIGNAL 0 (매수 대기)
  │ 활성 OB + 당일 존 터치 + 현재가 존 안(+0.25ATR) + 손절폭≤7% , 2회 연속
  │ STOP = 원격선 − 0.3ATR 확정, 수량 = R 사이징
  ▼
SIGNAL 1 (보유, 부분익절 전)
  ├─ 현재가 ≤ 청산선(STOP→본전@1R→트레일@2R) ─────────→ 전량 매도 → SIGNAL 3
  └─ 현재가 ≥ 진입가 + 2R → 50% 매도 ──→ SIGNAL 2
                                          └─ 현재가 ≤ 청산선 → 전량 매도 → SIGNAL 3
SIGNAL 3 ─ OBV z < −0.5 → SIGNAL 4 ─ OBV z > 0.5 → SIGNAL 0 (사용한 OB는 소멸, 새 OB 대기)
```

## 6. 구현 시 결정이 필요한 데이터·구조 사항

### 6.1 손절가 저장 — `SWING_TRADE.STOP_PRICE` (확정 2026-10-24)

오더블럭은 매수 다음 날 캐시에서 소멸하므로, 매수 시 확정한 손절가를 **DB에 영구 저장**한다.

```sql
ALTER TABLE SWING_TRADE
ADD COLUMN STOP_PRICE DECIMAL(15, 2) NULL COMMENT '매수 시 확정 손절가 (오더블럭 전략, 그 외 NULL)';
```

| 항목 | 결정 |
|------|------|
| 기록 | 매수 체결 시 `transition_to_buy(..., stop_price)` |
| 초기화 | 전량 매도 시 `reset_cycle`에서 NULL (`ENTRY_PRICE`·`PEAK_PRICE`와 같은 생명주기) |
| 단일 이평선 | 항상 NULL — 손절선을 매 사이클 진입가·완성봉 ATR로 재계산하므로 영향 없음 |
| NULL 폴백 | 편입(`adopt_position`)·컬럼 추가 전 데이터 → `진입가 × (1 − MAX_STOP_LOSS_PCT/100)` + warning 로그 |
| 반영 순서 | `create_all`은 기존 테이블에 컬럼을 추가하지 않는다 → **ALTER TABLE 수동 실행 후 배포** (entity만 먼저 배포하면 SELECT 실패) |

기각한 대안:
- Redis: TTL 만료·재시작 시 손절 기준이 사라져 포지션이 무방비가 된다.
- 기존 `EOD_SIGNALS`(String JSON): 읽고 쓰는 코드가 없는 미사용 컬럼이지만, 이름·용도가 달라 의미가 섞이고 파싱이 필요하다.
- `OB_LOW`(원격선) 저장: 손절가를 매일 ATR로 재계산할 때만 필요. 본 기획은 손절가 고정이므로 불필요.

### 6.2 나머지 연동 사항

## 7. 백테스트 정의 (`OrderBlockBacktestStrategy`, 일봉)

실전과 **같은 상수**를 공유하는 `BaseOrderBlockStrategy`를 두고 실전/백테스트가 상속 (단일 이평선의 `BaseSingleEMAStrategy` 구조와 동일).

| 항목 | 백테스트 규칙 | 선견 방지 포인트 |
|------|--------------|-----------------|
| OB 탐지 | 봉 i 판정 시 **i−1까지의 완성봉**만으로 탐지 | 피벗은 j+2봉 완성 후에만 확정 |
| ATR | 손절 버퍼·트레일링 모두 **i−1봉(전일 완성봉) ATR** | 실전은 장 전 캐시 ATR로 판정한다. 당일 봉 ATR은 당일 고저가 섞여 급락일에 청산선이 내려가는 선견이 된다 |
| 진입 | i봉 저가 ≤ 근접선 → 체결가 = `fill_buy(min(시가, 근접선))` (호가 올림 + 슬리피지 1틱) | 시가 < 원격선이면 갭 붕괴로 진입 없음 |
| 같은 날 손절 | 진입한 봉의 저가 ≤ STOP 이면 **손절로 간주** (`fill_sell(STOP)` 체결) | 일봉은 장중 순서를 모르므로 보수적으로 처리 |
| 추격 제한 | 일봉에선 현재가가 없어 3.1 #3을 재현할 수 없음 → 체결가를 근접선 이하로 강제하는 것으로 대체 | 의도적 차이 |
| PEAK | 전일 고가까지만 반영 (단일 이평선 백테스트와 동일) | 같은 봉 PEAK 갱신 + 청산 동시 발동 방지 |
| 청산 | 저가 ≤ 청산선 → `fill_sell(min(청산선, 시가))` (호가 내림 − 슬리피지 1틱) | 청산선 판정 자체는 슬리피지 없이 |
| 부분익절 | 고가 ≥ 진입가+2R → `fill_sell(max(목표가, 시가))` | 동일 |
| 비용 | 국내: 수수료 0.147% ×2 + 매도 거래세 0.20% / 미국: 수수료 0.25% ×2, 거래세 없음 (`trade_costs`) | 서비스 백테스트에도 반영 |
| 평가 종료 | 남은 보유분은 마지막 종가로 평가 (슬리피지 없음, 비용 반영) | |
| 연속 확인 | 1회 | 의도적 차이 (일봉 한계) |
| 최소 봉 수 | `min_bars` = EMA120 워밍업 + 1 | |
| 결과 | 기존 응답 + `strategy_stats` (탐지·터치·진입 수, 차단 사유, +1R 도달 일수, 청산 단계, 평균 R, 사이클별 순 R) | |

백테스트 클래스에는 v2 검증용 조건 스위치(시장 국면·주봉 구조·FVG·스윕·할인·저점 반등·직전 고점 목표·시간 청산)가
**기본 꺼짐**으로 들어 있다 — 실전 전략은 이 스위치를 읽지 않는다. 정의와 검증 절차는 `order-block-v2.plan.md`.

## 9. `describe()` 초안 (AI 종목 분석 전달용)

- **요약**: 상승 구조 돌파(BOS)를 만든 직전 음봉(오더블럭)까지 가격이 처음 되돌아올 때 사고, 오더블럭 하단 붕괴를 손절로 삼는다
