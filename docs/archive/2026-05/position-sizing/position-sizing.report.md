## 3. 변경 사항 요약

### 3.1 핵심 개념 변경

**기존 모델** (총 자산 기반):
```
RISK_PCT = 0.02 (2%)
MAX_POSITION_PCT = 0.25 (25%)
Position = INIT_AMOUNT × MAX_POSITION_PCT

→ 보수적 설계 (총 자산의 2-25%만 투입)
→ 다중 종목 배정금 모델에 부적합
```

**새 모델** (배정금 기반):
```
ENTRY_PCT = 0.5 (50%)        ← 기본 진입 비율
MAX_LOSS_PCT = 0.10 (10%)     ← 손절 손실 제한

Position = min(
    CUR_AMOUNT × ENTRY_PCT / 현재가,
    CUR_AMOUNT × MAX_LOSS_PCT / (현재가 - 손절가)
)

핵심: CUR_AMOUNT (배정금의 현재 가용 자본) 기반
→ 각 종목별 독립적 자본 할당
→ 수익금은 자동 복리, 손실금은 자동 위험 축소
```

#### 2. `app/domain/swing/trading/auto_swing_batch.py` (핵심)
**주요 변경**:
- 자본 추적: `INIT_AMOUNT` → `CUR_AMOUNT`로 변경
- 포지션 사이징 공식 (2가지 제약):
  ```python
  entry_qty = int(swing.CUR_AMOUNT * ENTRY_PCT / current_price)
  loss_limit_qty = int(swing.CUR_AMOUNT * MAX_LOSS_PCT / (current_price - stop_price))
  target_qty = min(entry_qty, loss_limit_qty)
  ```

- 매수 시 자본 차감: `swing.deduct_amount(executed_amount)`

- `target_qty <= 0` 조기 반환 (거래 불가능 상황)

**거래 흐름**:
```
초기 상태: CUR_AMOUNT = 1,000,000원

[1차 매수: 500,000원]
- 진입 수량 계산: min(entry_qty, loss_limit_qty)
- 체결 후: CUR_AMOUNT -= 500,000 = 500,000원

[1차 매도: +100,000원 수익]
- 체결 후: CUR_AMOUNT += 100,000 = 600,000원

[2차 매수: 300,000원]
- 진입 수량 계산: CUR_AMOUNT = 600,000 기반
- 체결 후: CUR_AMOUNT -= 300,000 = 300,000원

→ 수익금이 자동으로 다음 거래에 재투입 (복리)
→ 손실 시 자본 감소 → 다음 거래 규모 자동 축소 (안전성)
```

## 5. 핵심 설계 결정사항

### 5.1 의사결정 1: INIT_AMOUNT/CUR_AMOUNT 유지 (기존 삭제 재검토)

**고려사항**:
- 초기 검토 때 "INIT_AMOUNT는 불필요한 중복" → 삭제 제안
- 재검토 결과: **다중 종목 자본 할당 모델의 핵심**

**결정**: 두 필드 모두 유지
- `INIT_AMOUNT`: 종목별 초기 배정금 (모니터링, ROI 계산용)
- `CUR_AMOUNT`: 현재 가용 자본 (포지션 사이징, 거래 결정용)

**예시**:
```
종목 A 초기 할당금: 1,000,000원 (INIT_AMOUNT)
- 1차 매수 500,000원 체결
  → CUR_AMOUNT = 500,000원

- 1차 매도 600,000원 (100,000원 수익)
  → CUR_AMOUNT = 600,000원

ROI = (600,000 - 1,000,000) / 1,000,000 = -40%
but 거래 규모는 현재 600,000원 기반으로 결정

→ 수익금은 자동 복리, 손실금은 자동 위험 축소
```

### 5.2 의사결정 2: CUR_AMOUNT를 포지션 사이징 기초로 선택

**대안 검토**:
1. ❌ INIT_AMOUNT 기반: 고정 규모 → 손실 후에도 같은 규모 거래 (위험)
2. ❌ BALANCE 기반: 전체 계좌 자본 → 복수 종목의 상호 간섭 (복잡)
3. ✅ CUR_AMOUNT 기반: 배정금 내의 현재 자본 → 독립성 + 동적 위험 조절

**선택 이유**: 자동매매의 3가지 특성 구현
- **독립성**: 종목 A의 손실이 종목 B의 거래 규모에 영향 없음
- **동적 위험**: 수익 시 규모 확대, 손실 시 규모 축소 (자동)
- **복리**: 종목별 수익이 자동으로 다음 사이클 자본에 포함

### 5.3 의사결정 3: ENTRY_PCT(50%) + MAX_LOSS_PCT(10%) 2중 제약

**포지션 사이징 공식**:
```
Qty = min(
    CUR_AMOUNT × ENTRY_PCT / 현재가,        ← 1번 제약: 기본 진입 규모
    CUR_AMOUNT × MAX_LOSS_PCT / (현재가 - 손절가)  ← 2번 제약: 손절 손실 한계
)
```

**각 제약의 역할**:

| 제약 | 목적 | 상황 |
|------|------|------|
| ENTRY_PCT (50%) | 자본 배분 | **일반적인 경우 (제약이 되는 경우 90%)** |
| MAX_LOSS_PCT (10%) | 손실 보험 | **고변동성 종목 (손절가 멀 때만 작동)** |

**구체적 예**:
```
케이스 1: 안정적 종목 (손절가 5% 떨어짐)
- entry_qty (50% 기반): 100주
- loss_limit_qty (손절 10% 기반): 200주
→ 채택: min(100, 200) = 100주 (ENTRY_PCT가 제약)

케이스 2: 고변동성 종목 (손절가 50% 떨어짐)
- entry_qty (50% 기반): 100주
- loss_limit_qty (손절 10% 기반): 20주
→ 채택: min(100, 20) = 20주 (MAX_LOSS_PCT가 제약)
→ 의도: 변동성 큰 종목은 자동으로 위험 축소
```

### 5.4 의사결정 4: 변동성 기반 포지션 사이징 미채택

**검토 대상**: ATR(Average True Range) 기반 동적 사이징

**미채택 이유**:
- 변동성은 이미 **손절가 거리에 반영됨**
  - 고변동성 종목 → 손절가 멀어짐 → MAX_LOSS_PCT가 자동으로 제약
  - 저변동성 종목 → 손절가 가까움 → ENTRY_PCT가 그대로 적용
- 추가 변동성 지표는 **이중 가산(double-counting)** 위험
- ENTRY_PCT는 **고정 비율**로 충분 (자본 관리의 일관성)

**결과**: 단순하고 명확한 설계 유지

1. **테스트 전략 부재**
   - 설계 검증만 완료, 실제 거래 시뮬레이션 없음
   - **영향**: 실제 거래 시작 전 추가 검증 필요

2. **성과 측정 미예정**
   - "CUR_AMOUNT 기반이 더 나은가?" 데이터 없음
   - **영향**: 효과 입증이 주관적

3. **부분 체결 흐름 복잡성**
   - order_executor에서 단계적 CUR_AMOUNT 업데이트
   - **영향**: 부분 체결 버그 가능성 (추가 테스트 필요)

### 9.3 다음에 시도할 점 (Try)

1. **통합 테스트 프레임워크**
   - `pytest` + `fixture`로 CUR_AMOUNT 시나리오 테스트
   - 5가지 케이스: 연승, 연패, 부분체결, 손절, 이익실현

2. **성과 분석 대시보드**

3. **모니터링 알림 강화**
   - CUR_AMOUNT < threshold일 때 알림

4. **문서 버전 관리**

## 13. 참고 자료

### 13.1 설계 배경

본 리팩토링은 다음 배경에서 시작:
1. 기존 포지션 사이징이 총 자산 기반 → 다중 종목 배정금 모델 부적합
2. 수익금이 자동으로 복리되지 않음 (모든 거래가 INIT_AMOUNT 기반)
3. 손실 후에도 거래 규모 축소 안 됨 (위험 관리 미흡)

### 13.2 핵심 메커니즘

```
거래 흐름:
┌─────────────────────────────────────────┐
│ 1. 포지션 사이징                         │
│    min(entry_qty, loss_limit_qty)       │
├─────────────────────────────────────────┤
│ 2. 매수 체결                             │
│    swing.deduct_amount(executed_amount) │
├─────────────────────────────────────────┤
│ 3. 매도 체결                             │
│    swing.add_amount(executed_amount)    │
├─────────────────────────────────────────┤
│ 4. 다음 사이클                           │
│    CUR_AMOUNT (현재값) 기반 포지션 결정  │
└─────────────────────────────────────────┘

CUR_AMOUNT의 역할:
- 거래 규모의 동적 조절
- 수익금의 자동 복리
- 손실금의 자동 위험 축소
```
