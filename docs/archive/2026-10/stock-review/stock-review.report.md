### 주요 설계 결정

#### 1. Gemini API 인증 전략
- **선택**: 서버 API 키 하나 (`GEMINI_API_KEY`, 무료 등급)
- **이유**: 사용자 OAuth 토큰은 쿼터/요금이 OAuth 클라이언트 프로젝트로 가서 이득 없음
- **영향**: 기존 `/gemini` 도메인(OAuth 기반) 삭제
- **폴백 체인**: `gemini-3.8-flash` → 3.7 → 3.6 → 3.5 (Free Tier 503 대응)

#### 2. 백그라운드 처리 (응답 지연 대응)
- **문제**: Free Tier 응답이 60~130초 + 수시 503 에러
- **해결**: POST 즉시 RUNNING 반환 → 백그라운드 asyncio 작업 → 프론트 폴링(5초)
- **캐시 TTL**: 장중 30분 (데이터 자주 바뀜) / 장 밖 다음 평일 09:00 (시세·수급 미변화)
- **Redis 운영 방식**:
  - `stock_review:{mrkt}:{code}` = 결과 캐시 (사용자 공유)
  - `stock_review:running:{mrkt}:{code}` = 분석 중 표시 (토큰 기반, 30분 TTL, 중복 실행 방지)
  - `stock_review:waiters:{mrkt}:{code}` = 대기 사용자 목록
  - `stock_review:user:{user_id}` = 사용자별 24시간 분석 이력 (hash)

#### 3. DB 미기록 정책
- **원칙**: 등록 전 종목을 `STOCK_DAY_HISTORY`에 넣지 않음
- **이유**: `day_collect_job`이 해당 종목을 영구히 수집 대상으로 등록 (의도 아님)
- **결과 저장**: Redis만 사용 (분석은 '지금' 기준 → 과거 기록 쓸모 없음)
- **향후**: AI 판단을 자동매매에 연결할 때 최소 검증 기록만 DB 저장 예정

#### 4. KIS 데이터 선택 (Google Search grounding 대체)
- **문제**: Free Tier Gemini는 Google Search grounding 불가
- **해결**: KIS API에서 직접 수집
- **데이터 소스**:
  - 현재가 시세 + PER/PBR/시총/외인보유: `get_inquire_price()`
  - 6개월 일봉 (2회 호출, 100봉 제한): `get_stock_data()`
  - 투자자 동향: `get_investor_trend()` (TR FHKST01010900)
  - 재무 (분기/연간): `get_financial_statement()` (손익/비율/안정성)
  - 뉴스·공시 제목: `get_news_titles()` (TR FHKST01011800, 1회 40건 · 최근 7일까지 날짜를 거슬러 최대 7회)

#### 5. 데이터 처리 함정 (summary.py 구현)
- **분기 재무**: 연 누적 값 → 회계연도 말월(stac_month) 기준으로 이산 분기로 변환
- **연간 조회**: 첫 행은 진행 중 연도 → 제외
- **금액 단위**: 억원 (삼성 2024 매출로 검증: 300.9조)
- **뉴스 TR**: 종목코드 필터는 정상이나 응답 iscd1~10 에 등록 코드 일부만 실림 → 코드 또는 제목의 종목명으로 '종목' / 나머지는 '시장_업종'으로 분류
- **FID_TITL_CNTT**: "공백 필수" (제목 검색 불가)
- **가운뎃점 복구**: \x1a 깨진 문자 복원

#### 6. 인증 통일 (세션 계정 적용)
- **변경**: 요청마다 KIS 키를 다시 고르지 않고 한 번만 결정
- **이유**: 사용자 세션의 현재 선택 계정 (실계/모의) 적용, DB 조회 최소화
- **함수**: `kis_api.get_session_quote_auth()` (신규)

#### 7. 전략 설명 코드화
- **역할 분리**: 진입 타이밍은 전략(`SingleEMAStrategy`)이 판단 → Gemini는 판단만
- **구현**: `TradingStrategy.describe()` = 클래스 상수로 조립
- **사용처**: `TradingStrategyFactory.describe_all()` → 프롬프트 + 응답 스키마 enum
- **발견**: 손으로 쓴 이전 프롬프트의 전략 설명이 실제와 달랐음 (급등 필터를 '전일'로 기술 — 실제는 당일 등락률 ±5%, +DI>-DI·갭하락 차단·10분 연속 확인·매도 후 쿨다운 누락)
- **CLAUDE.md 갱신**: 전략 정의 규칙 추가 (차후 전략 추가 때 참고)

#### 8. 사전 차단 (Gemini 호출 전)
- 관리종목, 투자위험, 거래정지, 정리매매 → Gemini 없이 즉시 "부적합"
- Gemini 대기 비용 절감

## 주요 학습 사항

### 잘된 점
1. **Free Tier 활용**: Gemini 3.8 Flash로 충분한 품질 확보 (무료, 응답 구조화 가능)
2. **백그라운드 처리 패턴**: 장시간 작업(60~130초)을 폴링으로 처리 → 사용자 경험 개선
3. **Redis 원자성**: Lua 스크립트로 토큰 검증·삭제의 race condition 방지
4. **KIS 데이터 함정 대응**: 분기값 누적 변환, 뉴스 TR 제목 보완 등 치밀한 처리

### 개선 기회
1. **설계 문서 없이 진행**: 채팅 합의로 빠르게 진행했지만 Match Rate 기준이 없어 리뷰에 의존 — 규모가 큰 기능은 Plan/Design 문서를 남기는 편이 추적에 유리
2. **다전략 지원**: 현재 'S'(단일 20EMA) 하나 → 확대 시 per-strategy 백테스트 결과 표시
3. **국제화**: 미국 종목은 Finnhub, 국내는 KIS 분기 처리 (향후)
4. **DB 이력**: AI 판단을 자동매매에 연결할 때 검증용 최소 기록 사전 준비

### 향후 적용
- 새 AI 기능도 무료 모델 + 백그라운드 처리 + 스토어 단일 폴링 패턴을 재사용
- 다중 전략 등록 시 각 전략별 백테스트 성과를 분석 결과에 함께 전달
- KIS의 해외 재무 부재 시 Finnhub 등 외부 소스 조건부 통합 (비용 검토)

## 결론

**stock-review** 기능으로 사용자가 스윙 등록 전 종목에 대해 AI 판단(적합/보류/부적합)과 근거, 추천 전략을 확인할 수 있게 되었습니다.

- **기술**: Free Tier Gemini + 백그라운드 폴링으로 60~130초 지연 흡수
- **데이터**: KIS에서 시세·재무·수급·뉴스를 직접 수집 (함정 처리 완료)
- **품질**: 201개 테스트 + 라이브 KIS/Gemini 호출 + 2회 코드 리뷰 → 17건 수정
- **준비도**: 배포 즉시 가능 (환경 변수만 설정하면 됨)

향후 다전략이 추가되면 AI가 각 전략의 백테스트 성과를 고려해 추천하는 고도화도 계획 중입니다.
